## 测量口径调整

- TemplateComparison 的 Meepo 字节输出改为直接调用当前 `merge(ctx, OutputStream, Charset)`，移除历史 API 的反射回退。
- Writer 计时返回填充后的 StringWriter，省去计时区内的 toString 快照。
- 共享模板初次测量按线程编号选择分支，导致分支比例随线程数变化。统一分支条件后重新执行 48 组测量，汇总采用重测结果。
- 汇总使用 96 组单线程热渲染、24 组模板创建与首次输出、48 组共享模板多线程测量，共 336 个独立 fork。
- JFR 热点定位另外使用 4 个独立 fork。JSON、日志和录制文件在分析完成后清理。
- 相对指数和名次由文档公布的舍入均值计算，共 9 张对照表、216 项排名与指数。分配量为 0 B/op 的基准行采用绝对值排名。

## 评估方法

先检查模型、空值、函数覆盖、作用域、代理字符、并发与异常语义，再运行完整输出的基准。
String 缓存命中、复制到 Writer、返回 UTF-8 字节是不同契约，应分行比较。
不能把数组、MethodHandle、少一次回调或 Map 改造本身视为提速证据；改善必须通过当前实现的重新测量确认。

Meepo 保持 Java 8 生产字节码；JDK 私有 API 或反射实验只在测试基准中研究。
历史 Javadoc 摘要保留测量条件与较慢场景；仓库不保存原始计时结果、baseline class 或生成报告的脚本。
