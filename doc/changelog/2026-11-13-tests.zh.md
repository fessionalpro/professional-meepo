## 经证明冗余的判断

以下方向受算法不变量约束，增加普通模板输入也不能到达，因此精简判断并保留相关边界测试。

| 位置 | 不变量与处理 |
|:--|:--|
| `RnaEach.loop` | Collection 分支已经返回或转成数组；剩余入口一定是数组，移除恒真的 `isArray()` 外层判断。 |
| `Case.wordCase` 两个重载 | `'-'` 不是 Java 标识符字符；在 `isJavaIdentifierPart(c)` 为 true 的分支中移除 `c == '-'`，非标识符分支仍处理连字符。 |
| `Parser.findXnaGrp` | 扫描区间不包含右边界，结果必小于 `main1`；只需保留左边界判断。 |
| `Parser.bornHiMeepo` | 无尾词且尚未到 EOF 时，扫描只能停在 LF；移除重复的换行判断。 |
| `Parser.toGene` | `okGene()` 保证有且仅有根帧；用 `removeLast()` 取得根帧，代替 `pollLast()` 后的恒真断言，关闭 assertions 时也能明确失败。 |
| `Life.parse` | 区间数组长度只有 1 或 2；排除 1/1 和 2/2 后，混合分支的第二个长度判断是重复条件。 |

没有用反射注入非法数组、破坏私有解析栈或制造并发竞争来增加覆盖数字。
同组 DONE 的防御仍保留，因为它对受保护的解析器扩展入口有意义。

## 补测发现的实际缺陷

`Life` 在遇到不相交项时未前移归并游标，例如 `1,3,3` 留下重复项，`1-2,5-7,6-9` 不能归并后两段。
修复三个不合并分支的游标更新。仅含空白的 scope 先 trim 后按空 scope 处理；区间排序改用 `Integer.compare`，
防止 `0--2147483648,2` 等已被数字解析接受的输入使减法比较溢出。

资源路径、注解处理器和命令参数的回归分别由 `ResourceSecurityTest`、`CompilerSecurityTest`、`ArgumentBoundaryTest` 验证。

## 复现覆盖率

完整旧测试集包含 Nashorn 测试，使用完整 JDK 8：

```sh
mvn -Pcoverage clean verify -Dmaven.javadoc.skip=true -Dmaven.source.skip=true
```

`jre-jdk8` 自动添加 `src/test/jdk8`，因此单次 Java 8 `verify` 就能达到全部覆盖门槛。
HTML 报告在 `target/site/jacoco/index.html`，XML 在同目录；`verify` 会在任一门槛不足时失败。

切换完整 JDK 21 后可直接执行全量测试。`nashorn-jdk15` 在 JDK 15 及以上添加 test scope 的独立 Nashorn 15.7，
现有 JS 用例也参与执行。`jmh-jdk17` 添加完整引擎比较和现代运行时环境测试，后者需要 JDK 自带的 `jlink`。

```sh
mvn clean test
```

若需保留 Java 8 的覆盖报告和生产字节码，可以只清理 `target/test-classes`、`target/generated-test-sources`，
随后在 Java 21 执行以下命令。

```sh
mvn -Dmaven.main.skip=true test
```

JaCoCo 按 class ID 关联执行数据，跨编译器合并时应使用同一份生产 class。
切换 JDK 后应清理旧测试 class，避免 Java 8 加载 Java 17 测试字节码。
执行与依赖管理约定见 [JMH Prompt](../prompt/jmh.prompt.md)。
